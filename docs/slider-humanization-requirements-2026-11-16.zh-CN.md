## 2. 现行实现的问题定位（`slidex/_trajectory.py::generate_trajectory`）

对照人手运动学（minimum-jerk 主导 + 生理性震颤 + Fitts 定律时长），当前轨迹有 6 处可被统计识别的机器特征：

| # | 现状（代码位置） | 问题 | 人手特征 |
|---|---|---|---|
| P1 | **中段 20%–60% 纯线性匀速**：`eased = 0.15 + 0.60 * t` | 匀速段是滑块风控最经典的统计签名（速度直方图出现平顶） | 速度呈钟形（bell curve），全程无匀速段；加速度连续 |
| P2 | 四阶段分段 easing，**段边界速度一阶不连续**（20%/60%/85% 三处折角） | 速度曲线出现三个硬拐点，二阶导跳变 | minimum-jerk：x(t) = D·(10τ³−15τ⁴+6τ⁵)，加速度在起终点为零、处处连续 |
| P3 | 事件间隔 `random.uniform(25, 45)` 为主 | 均匀分布太规整；间隔直方图呈矩形 | 间隔近似 gamma/对数正态分布，右偏、有长尾；偶发 100–300ms 犹豫停顿 |
| P4 | 总时长恒定 ~600ms 量级（15 点 × 25–75ms），与距离基本无关 | 同距离同时长，跨会话方差小 | Fitts 定律：时长 ∝ log2(D/W)，短距 300ms、长距可到 1s+，个体还有快/慢人设 |
| P5 | Y 轴抖动 = 单叶正弦 `sin(p·π·k)` × 随机相位 | 解析单正弦谱线干净，频谱单一尖峰 | 生理性震颤 8–12Hz 多模态叠加 + 缓慢漂移，频谱宽带 |
| P6 | X 轴严格贴合理想曲线（`x = distance * eased`，零偏差） | X 无噪声 = 完美路径；人手对理想路径有 ±0.3–1px 随机偏离 | 真实指点有路径噪声，且常含 1–2 次子动作（sub-movement）修正 |
| P7 | 过冲回拖固定模式：+3–6px → −2–3.5px → ±1px 三连（`_drag.py::build_drag_events` extra_overshoot 恒定追加） | 微修正动作程式化，每次拖动同构 | 过冲是概率行为（约 30–60% 试验出现），幅度方向随机，偶尔多次修正、偶尔没有 |

另：`steps = randint(10, 15)` 与固定四阶段比例意味着**所有拖动共享同一骨架**，仅参数微调——跨会话聚合同一骨架即可聚类识别。

> 注：`_trajectory_pool.py` 已有真人录制轨迹池与 `recorded_trace_verdict` 质检。真人回放是现成的最优素材，本需求与之互补（见 R8）。

## 3. 需求条目

### R1 主曲线换 minimum-jerk（P1/P2，最高优先）

以五次光滑曲线为母线替换分段线性 easing：

```
τ = i / (steps-1)
eased(τ) = 10τ³ − 15τ⁴ + 6τ⁵          # 速度钟形、加速度处处连续、起终点加速度=0
```

- 允许在母线上做 ±5% 的速度不对称（前段慢/后段慢随机二选一，模拟个体差异）。
- **验收硬指标**：速度序列的一阶差分曲线在段内无平顶段（匀速占比 < 5%）、无跳变点（相邻差分比 < 2.5）。

### R2 子动作（sub-movement）合成（P6/P7）

主拖动由 2–4 个重叠/衔接的子动作构成：

- 首子动作 ballistic 覆盖 85–98% 距离；余下 1–2 个修正子动作各覆盖剩余距离的 50–100%，每个修正子动作自身也是 min-jerk 小曲线；
- 子动作之间允许 0–180ms 停顿（概率 30%）；
- 修正次数随机：0 次修正（一步到位）应占 ~25%，1 次占 ~50%，2 次占 ~25%。

### R3 时间模型：Fitts 定律 + gamma 间隔（P3/P4）

- 总时长基线：`T = clamp(320 + 900 * log2((D+40)/40) / 3.5, 380, 1500) ms`，再乘个体速度系数 `uniform(0.75, 1.5)`（快手/慢手人设，同一会话内保持一致）；
- 事件间隔从 **gamma 分布**采样（shape≈2.2，按均值归一到 T/steps），并保留 5–10% 概率插入 100–300ms 犹豫停顿；
- 禁用 `random.uniform` 作为间隔主采样（可作为叠加微抖 ±3ms）。

### R4 震颤与路径噪声（P5/P6）

- Y 轴：2–3 个 8–12Hz 阻尼振荡叠加（幅度各 0.4–1.2px，随机相位）+ 缓慢线性漂移（当前 drift 保留）；
- X 轴：对理想路径叠加 AR(1) 噪声（σ≈0.4px，ρ≈0.7），终点强制回到目标位；
- 全部噪声在 mouseup 前 3–4 点内收敛到目标 ±0.5px（避免终点飞出）。

### R5 过冲概率化（P7）

- 出现概率 30–60% 随机；幅度 `uniform(2, 9)px`、回拖 `uniform(1, 4)px`；
- 15% 概率出现两次修正；`overshoot_back=False` 时也可能出现小幅终点抖动（±0.8px）而非完全干净的停止；
- 删除 `_drag.py::build_drag_events` 里恒定追加的固定三连模式，改由 GesturePlan/轨迹层统一决定。

### R6 骨架多样性（P2/P4 跨会话统计）

每次拖动独立随机：steps ∈ [12, 22]、阶段比例扰动 ±15%、速度人设系数、子动作数、过冲有无。**同一会话内的连续拖动不得共享同一组骨架参数**。

### R7 成功判定契约修复（11-16 实证 bug，独立于拟人化，建议先修）

**现状**：上游返回 `{success: true, verifyResult: false, verifyCode: F001}` 时 `solve_on_page` 仍返回 `True`（页面实际未放行，后续流程空转）。

要求：

1. solver 内部必须解析验证回执（console 事件 / 网络响应 / 页面文案「验证失败」三通道任一）；
2. `SolveResult` 增加 `verified: bool` 与 `upstream_code: str|None` 字段——「滑块拖完」(solved) 与「上游确认放行」(verified) 分离；
3. `solve_on_page` 返回值语义改为 verified；未拿到回执时返回 `verified=False, reason=no_receipt`（宁缺勿假）；
4. 调用方（register_new.py 等）据此区分「重试同会话无意义（F001 类）→ 换新会话」与「几何未命中（F015 类）→ 重取图」。

### R8 真人池回放优先（可选增强）

aliyun provider 场景默认优先从 `_trajectory_pool` 真人录制池回放（现有质检 `recorded_trace_verdict` 已过滤脏录制），对录制轨迹做时间缩放（×0.8–1.25）+ R4 噪声叠加后再回放；合成轨迹作为池空/池质检失败时的兜底。回放命中时日志标注 `source=pool:<file>` 便于线上归因。

## 4. 验收标准

1. **线上通过率**：z.ai 注册场景连续 20 个全新会话自动求解，verified 通过率 ≥ 85%，其中 F001 拒绝 ≤ 2 次（当前基线：双号注册 1/2 会话首跑被 F001 拒）。
2. **统计特征**：对 R1–R6 产出的轨迹抽样 100 条——匀速段占比 < 5%；间隔分布 Kolmogorov–Smirnov 检验不拒绝 gamma 拟合（α=0.05）；总时长与距离呈正相关（Pearson r > 0.4）。
3. **无回归**：现有回归测试全绿；`test_image_selectors_cover_both_dom_shapes`、`TestGetResultFailureShape` 等既有用例不回退。
4. **契约**：R7 新增单测——模拟上游 `verifyResult:false` 时 `solve_on_page` 必须返回非成功结果。
